# Database Migrations

This directory contains database migrations for the PMP Auth API PostgreSQL storage backend.

## Tool: dbmate

We use [dbmate](https://github.com/amacneil/dbmate) for managing database migrations.

- **Image**: `amacneil/dbmate:2.28.0`
- **Migration directory**: `db/migrations/`
- **Schema file**: `db/schema.sql` (auto-generated)

## Migration Workflow

### Docker Compose (Automatic)

Migrations run automatically when starting services via Docker Compose:

```bash
# Start all services (migrations run automatically)
docker-compose up -d

# View migration logs
docker-compose logs database_migrations

# Check migration status
docker-compose run --rm database_migrations status
```

The `database_migrations` service:
- Waits for PostgreSQL to be healthy
- Runs all pending migrations
- Exits successfully
- The app service waits for migrations to complete before starting

### Manual Migration Commands

```bash
# Check migration status
docker-compose run --rm database_migrations status

# Run pending migrations
docker-compose run --rm database_migrations up

# Rollback last migration
docker-compose run --rm database_migrations down

# Rollback all migrations
docker-compose run --rm database_migrations down --all

# Create a new migration
docker-compose run --rm database_migrations new migration_name
```

### Local Development (without Docker)

Install dbmate locally:

```bash
# macOS
brew install dbmate

# Linux/Windows
# Download from https://github.com/amacneil/dbmate/releases
```

Set database URL:

```bash
export DATABASE_URL="postgresql://pmp_user:pmp_password@localhost:5432/pmp_auth?sslmode=disable"
```

Run migrations:

```bash
# From project root
dbmate up

# Check status
dbmate status

# Create new migration
dbmate new add_some_feature
```

## Migration Files

Migrations are SQL files in `db/migrations/` with the format:

```
YYYYMMDDHHMMSS_migration_name.sql
```

Each file contains:

```sql
-- migrate:up
-- SQL statements to apply the migration
CREATE TABLE ...;

-- migrate:down
-- SQL statements to rollback the migration
DROP TABLE ...;
```

   - Enables OIDC session management and logout coordination

## Schema Verification

The `schema.sql` file is auto-generated by dbmate and should not be edited manually.

To regenerate schema from current database:

```bash
docker-compose run --rm database_migrations dump
```

## Environment Variables

The migration service uses:

- `DATABASE_URL`: PostgreSQL connection string
- Configured in `docker-compose.yml`

## Service Dependencies

```
postgres (healthy)
  ↓
database_migrations (completed successfully)
  ↓
pmp-auth-api (starts)
```

This ensures:
1. PostgreSQL is ready to accept connections
2. All migrations have been applied
3. Application starts with correct schema

## Troubleshooting

### Migrations fail to run

Check PostgreSQL is healthy:
```bash
docker-compose ps postgres
docker-compose logs postgres
```

### Migration stuck waiting

Increase wait timeout in docker-compose.yml:
```yaml
command: --wait --wait-timeout 120s up
```

### Reset database (development only)

```bash
# Stop all services
docker-compose down

# Remove PostgreSQL volume (DESTROYS ALL DATA)
docker volume rm pmp-auth-api_postgres_data

# Start fresh
docker-compose up -d
```

### Check migration history

Dbmate creates a `schema_migrations` table to track applied migrations:

```sql
SELECT * FROM schema_migrations;
```

## Best Practices

1. **Never edit applied migrations** - Create a new migration instead
2. **Test rollback** - Ensure `migrate:down` works
3. **Keep migrations atomic** - One logical change per migration
4. **Use transactions** - Most DDL statements in PostgreSQL are transactional
5. **Add indexes separately** - Consider impact on large tables
6. **Document breaking changes** - Add comments for schema changes

## Creating New Migrations

```bash
# Create new migration
docker-compose run --rm database_migrations new add_user_roles

# Edit the generated file in db/migrations/
# Add your SQL in the migrate:up section
# Add rollback SQL in the migrate:down section

# Test the migration
docker-compose run --rm database_migrations up

# Test rollback
docker-compose run --rm database_migrations down
```

## Production Deployment

For production:

1. Review all pending migrations
2. Run migrations during maintenance window
3. Verify schema changes don't break running app
4. Keep database backups before migrations
5. Monitor migration logs for errors

Example:
```bash
# Backup database first
pg_dump -U pmp_user pmp_auth > backup.sql

# Run migrations
dbmate up

# Verify
dbmate status
```
